## 1. ที่มาและวัตถุประสงค์

ความรู้การปฐมพยาบาลกระจายอยู่ในหลายหัวข้อ การค้นข้อมูลจากคำถามภาษาไทยจึงต้องเลือกทั้งหัวข้อ กลุ่มอายุ และเงื่อนไขของผู้ป่วย โครงการนี้สร้างแชตบอทที่ค้นข้อมูลก่อนตอบด้วย Retrieval-Augmented Generation (RAG) และใช้ Knowledge Graph เชื่อมบทความที่เกี่ยวข้อง เพื่อศึกษาว่าการค้นแบบผสมช่วยครอบคลุมหลักฐานสำหรับคำถามที่ต้องอ้างอิงหลายหัวข้อได้เพียงใด

วัตถุประสงค์คือ (1) จัด corpus ที่ตรวจสอบที่มาได้ (2) เก็บข้อมูลทั้งฐานเวกเตอร์และกราฟ (3) ตอบภาษาไทยพร้อมหลักฐาน (4) เปรียบเทียบ Vector RAG กับ Vector+Graph RAG และ (5) ประเมินแยกคำถามตรงกับคำถามเชื่อมโยง รวมทั้งค่าเฉลี่ยสองกลุ่ม

เป็นต้นแบบเพื่อการเรียน ไม่ใช่ระบบวินิจฉัยหรือระบบช่วยเหลือฉุกเฉินที่ได้รับการรับรอง หากเป็นเหตุฉุกเฉินในประเทศไทย ให้โทร 1669 และทำตามเจ้าหน้าที่

## 2. ข้อมูลที่ใช้

นำเข้าบทความจาก St John Ambulance 29 หัวข้อ ครอบคลุมทั้งเบื้องต้น เช่น แผลถลอก เลือดกำเดา แผลไหม้ ข้อแพลง และหัวข้อเฉพาะ เช่น CPR/AED สำลักแยกอายุ ชัก แพ้รุนแรง จมน้ำ ไฟฟ้าช็อต ลมแดด สารพิษ บาดเจ็บศีรษะและสันหลัง ข้อมูลต้นฉบับเป็นภาษาอังกฤษ ส่วนคำถามและคำตอบเป็นภาษาไทย

ดึงเฉพาะเนื้อหาหลังชื่อบทความ ตัด navigation, footer, ส่วนบริจาค และบทความที่แนะนำท้ายหน้า เพื่อลดข้อความซ้ำและการปะปนข้ามหัวข้อ เก็บไฟล์ต้นฉบับ URL ผู้เผยแพร่ กลุ่มอายุ เวลาดาวน์โหลด และ hash ใน data/ การดาวน์โหลดจากเว็บไซต์ทางการไม่เท่ากับได้รับสิทธิ์เผยแพร่ corpus ต่อ

ข้อมูลภาษาไทยของสภากาชาดไทยและแนวทาง IFRC อยู่ในรายการแหล่งอ้างอิงสำหรับขยายและตรวจเทียบ ยังไม่ได้รวมทั้งคู่มือเข้าดัชนีที่ทดลองนี้ ไม่ใช้วันที่อัปโหลดเว็บแทนปีที่ปรับปรุงแนวทาง

## 3. เครื่องมือและเทคนิค RAG

| ส่วน | การตั้งค่าที่ใช้ |
|---|---|
| LLM ตอบ | Qwen3-4B-Instruct-2507, GGUF Q4_K_M จาก Unsloth |
| Runtime | llama.cpp, local OpenAI-compatible API |
| Embedding | Qwen3-Embedding-0.6B, GGUF Q8_0, 1024 มิติ, last pooling |
| Vector database | Qdrant Local แบบ persistent บนดิสก์ |
| Chunking | ตามย่อหน้า เป้าหมาย 220 คำภาษาอังกฤษ overlap 40 คำ |
| Similarity | Cosine similarity |
| Retrieval | candidates 12 → vector k=5, ไม่เกิน 2 chunks ต่อเอกสาร |
| Graph retrieval | RELATED_GUIDANCE 1 hop เพิ่มไม่เกิน 3 เอกสาร แล้วค้น chunk ด้วยเวกเตอร์ |
| Context budget | 10000 ตัวอักษร โดยไม่ตัดข้อความกลาง chunk |
| Knowledge Graph | NetworkX MultiDiGraph บันทึก node-link JSON ถาวร |
| Generation | temperature 0.1, max output 650 tokens, runtime context 8192 tokens |
| Interface | FastAPI + HTML/CSS/JavaScript |
| Capture | Playwright เปิดผลสนทนาจริงที่บันทึกไว้บนเว็บ |

กราฟประกอบด้วย Topic, AgeGroup, Chunk, Source, Sign, GuidanceStep และ Contraindication ความสัมพันธ์ HAS_SIGN, HAS_GUIDANCE, HAS_CONTRAINDICATION, SUPPORTED_BY, APPLIES_TO, HAS_EVIDENCE, FROM_SOURCE และ RELATED_GUIDANCE ข้อความอาการ ขั้นตอนและข้อห้ามเก็บจากต้นฉบับพร้อมเงื่อนไข โดยเส้นเชื่อมข้ามหัวข้อเป็น routing ที่ผู้พัฒนาโปรเจกต์กำหนดพร้อม URL สองฝั่ง ไม่ใช่คำวินิจฉัยที่อนุมานจากกราฟ โมเดลต้องใช้ข้อความต้นฉบับเป็นหลักฐาน

วิธีทำงาน: รับคำถาม → สร้าง query embedding → ค้น Qdrant และกรองอายุเมื่อระบุชัด → ดึงหัวข้อใกล้เคียงในกราฟสำหรับโหมดผสม → รวมข้อความ → ให้ Qwen ตอบพร้อม [S1], [S2] → แสดงลิงก์และบันทึกผล JSON ระบบตรวจรหัสอ้างอิงว่ามีจริง แต่การตรวจรหัสไม่รับประกันว่าเนื้อหาอ้างอิงรองรับข้ออ้าง

Similarity threshold 0.3 เป็นค่าเริ่มต้น ไม่ใช่ค่าความเชื่อมั่นหรือเกณฑ์ปลอดภัยทางการแพทย์ จัดชุดพัฒนาแยกต่างหากสำหรับสำรวจ k=3,5,8 ผลดู results/dev_retrieval.json

## 4. การออกแบบการทดลอง

ชุดคำถาม 20 ข้อ แบ่ง direct 10 ข้อและ multihop 10 ข้อ ใช้คำถามชุดเดียวกันกับ Vector RAG และ Vector+Graph RAG รวม 40 บทสนทนา แต่ละข้อระบุ checklist เฉลยและ required_documents สำหรับตรวจความครอบคลุมหลักฐาน เฉลยและชุดคำถามไม่ถูกนำเข้าฐานที่แชตบอทใช้ค้น

คำถามตรงมีคำตอบในหัวข้อเดียว เช่น ท่าที่เหมาะสมเมื่อเลือดกำเดาไหล หรือข้อห้ามระหว่างชัก คำถามเชื่อมโยงต้องรวมเงื่อนไข/ขั้นตอนจากหลายหัวข้อ เช่น หลังชักไม่หายใจปกติแล้วเปลี่ยนไป CPR/AED หรือแมลงต่อยร่วมสัญญาณแพ้รุนแรง

ประเมินคุณภาพด้านความถูกต้อง ความครบถ้วน ความปลอดภัย ความชัดเจน และอ้างอิง ด้านละ 0–4 รวม 20 คะแนนต่อข้อ ผู้ประเมิน LLM คือ Codex ในแชตที่สร้างโปรเจกต์นี้ ซึ่งเป็นคนละโมเดลกับ Qwen ผู้ตอบ อ่านคำตอบจริงเทียบเฉลยและหลักฐานพร้อมระบุเหตุผล คะแนนไม่ใช่ผลจากบุคลากรทางการแพทย์และไม่ได้เป็นผู้ประเมินอิสระที่ไม่เกี่ยวข้องกับการสร้างเฉลย มีแบบฟอร์มมนุษย์แยกให้ตรวจซ้ำโดยเว้นคะแนนไว้

Document evidence recall = จำนวนหัวข้อใน required_documents ที่ดึงเข้าบริบทจริง / จำนวนหัวข้อที่ต้องใช้ทั้งหมด วัดการค้นหลักฐาน ไม่ใช่ความถูกต้องคำตอบ ค่าเฉลี่ยคะแนนแต่ละกลุ่ม = ผลรวมคะแนน / จำนวนข้อ ค่าเฉลี่ยสองกลุ่ม = (direct mean + multihop mean) / 2

ผลทดลองเบื้องต้นของ Qwen3-1.7B พบการกลับความหมายคำแนะนำเลือดกำเดา จึงเก็บไว้ใน results/pilot_qwen_1_7b และเปลี่ยนโมเดลก่อนเก็บผลชุดสุดท้าย ข้อ D01 จึงเคยถูกเห็นระหว่างเลือกโมเดล ผลชุดสุดท้ายเป็นการประเมินเชิงพัฒนา ไม่ใช่ blind held-out benchmark และควรยืนยันซ้ำด้วยชุดคำถามใหม่

## 6. ข้อจำกัดและการพัฒนาต่อ

ผลไม่รับรองประสิทธิภาพทางคลินิก ชุดข้อมูลหลักมีผู้เผยแพร่รายเดียว ต้นฉบับเป็นภาษาอังกฤษ การแปล การรักษาคำปฏิเสธและเงื่อนไขอาจผิด ความสัมพันธ์กราฟเลือกด้วยผู้พัฒนา และ gold topics อาจไม่ครอบคลุมหลักฐานทางเลือกทั้งหมด ผู้ประเมิน LLM มีอคติและไม่แทนการตรวจโดยผู้เชี่ยวชาญ จำนวนคำถามยังน้อย การไม่พบอ้างอิงผิดไม่ได้แปลว่าไม่มี hallucination

การพัฒนาต่อควรตรวจ corpus/เฉลยโดยผู้สอนปฐมพยาบาล เพิ่มภาษาไทยและเทียบแนวทางปัจจุบัน บันทึกข้อขัดแย้งแยกตามประเทศ เพิ่มชุดคำถามใหม่ที่ยังไม่เคยใช้ปรับโมเดล รวมคำถามนอกขอบเขต อายุกำกวม และหลายเงื่อนไข เพิ่ม reranker และ calibrate การปฏิเสธตอบ ตลอดจนให้คนประเมินคู่ขนานกับ LLM
